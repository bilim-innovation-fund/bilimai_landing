# Блог — MDX-посты из бэкенда

## Назначение

Блог для учителей на `/ru/blog` и `/kk/blog`. Посты генерирует бэкенд (`ai_platform_back/apps/blog`, агенты `blog_writer` и `blog_translator`), редактор проверяет их в Django-админке и выгружает zip-пакетом. Разработчик распаковывает пакет в этот репозиторий и открывает PR. Инварианты:

- только ru и kk; английский интерфейс ведёт в `/ru/blog` (редирект `/en/blog*` → `/ru/blog*` в `next.config.ts`);
- формат файлов задаёт бэкенд: `ai_platform_back/apps/blog/bundle.py` (`FORMAT_VERSION = 1`) и `ai_platform_back/docs/ru/apps/BLOG.md`, раздел «Контракт пакета». Зеркало здесь — `src/lib/blog/{types,frontmatter,validate}.ts`. Меняется формат — правятся обе стороны;
- подпись на сайте — только «Команда Bilim AI» / «Bilim AI командасы», без AI-метки и имени рецензента; `generatedBy` нигде не выводится;
- всё пререндерится; сломанный пост роняет `next build` сообщением `файл:строка: причина`.

## Публикация

1. В админке — action «Скачать пакет для лендинга (публикует)». Один пост приходит как `blog-<slug>.zip`, несколько — как `blog-bundle-<YYYY-MM-DD>.zip`.
2. `unzip -o blog-<slug>.zip -d bilimai_landing/`
3. `corepack pnpm@10.34.6 build` — валидатор напечатает предупреждения и упадёт на ошибках.
4. PR → merge в `main` → Vercel.

**Правка опубликованного поста** — тем же action повторно. `date` не меняется, `updated` обновляется. Если в админке заменили обложку, у неё новое имя `cover-<hash8>.jpg`, а `unzip -o` старый файл не удаляет. Удалите его вручную: валидатор предупредит о файле, на который не ссылается ни один пост.

**Снять пост**: «Снять публикацию» в админке файлы на лендинге не трогает. Удалите оба `.mdx` и папку `public/images/blog/<slug>/` в PR.

**Смена slug** после публикации — это новые пути и новый `group`. Удалите старые файлы и добавьте в `next.config.ts` постоянный редирект `/:lang(ru|kk)/blog/<старый>` → `/:lang/blog/<новый>`.

После деплоя можно заполнить в админке `landing_url` = `https://bilimai.kz/ru/blog/<slug>` (справочное поле).

**Ручной пост** (не из админки): скопируйте `src/content/blog/_template/post.mdx` в `ru/<slug>.mdx` и `kk/<slug>.mdx`, положите обложку, заполните фронтматтер. В шаблоне `draft: true` — поменяйте на `false`, иначе пост останется черновиком: в `next dev` он виден, а в прод-сборку, sitemap и RSS не попадёт (сборка напечатает предупреждение). `generatedBy` не ставьте. `readingMinutes` можно не указывать: тогда он считается по числу слов (180 в минуту).

## Фронтматтер

Ровно эти 13 ключей. Порядок не проверяется, `_template/post.mdx` его повторяет. Неизвестный или повторный ключ — ошибка: новый ключ означает `FORMAT_VERSION 2` на бэкенде.

| Ключ | Обязательный | Правило |
|---|---|---|
| `title` | да | строка, ≤ 70 символов (кодпоинты) |
| `description` | да | строка, 50–160 символов после trim |
| `date` | да | `YYYY-MM-DD` без кавычек — это **строка**; день первой выгрузки по Asia/Almaty, дальше не меняется |
| `updated` | нет | `YYYY-MM-DD`, не раньше `date`; бандл пишет его всегда. «обновлено …» и `article:modified_time` выводятся, только если `updated > date` |
| `author` | да | id из `src/content/authors.ts`; из бандла всегда `"bilimai-team"` |
| `group` | да | равен slug из пути |
| `category` | да | одна из рубрик ниже |
| `tags` | да | список `[...]`, можно `[]`; элементы приводятся к строке; на странице не показываются (только «Читайте также» и `article:tag`) |
| `cover` | да | `/images/blog/<slug>/cover-<hash8>.jpg`, файл должен существовать в `public/` |
| `coverAlt` | да | строка, может быть `""` (тогда предупреждение) |
| `generatedBy` | нет | служебная метка бэкенда (`"bilim-ai-writer@1"`), нигде не выводится |
| `readingMinutes` | нет | целое ≥ 1, показывается как есть |
| `draft` | да | `true`/`false`; черновики видны только в `next dev` и не попадают ни в сборку, ни в sitemap, ни в RSS |

Грамматика (`frontmatter.ts`): файл начинается с `---`; дальше строки `ключ: значение`, закрывающая `---`, пустая строка и тело. Разрешены значения:

- строки в двойных кавычках — внутри только экранирования `\\` и `\"`;
- голые даты;
- целые числа;
- `true`/`false`;
- однострочные списки `[a, b]` из тех же скаляров.

Блочные списки `- x`, вложенность, одинарные кавычки, строки без кавычек и комментарии — ошибки. gray-matter и js-yaml не используются: они превращают даты в `Date`.

**Рубрики** (копия `apps/blog/models.py::CATEGORY_LABELS`; подпись выводится на карточке, в посте и в `articleSection`):

| `category` | ru | kk |
|---|---|---|
| `lesson-ideas` | Идеи для уроков | Сабақ идеялары |
| `planning` | Планирование (ҚМЖ) | Жоспарлау (ҚМЖ) |
| `assessment` | Оценивание (БЖБ/ТЖБ) | Бағалау (БЖБ/ТЖБ) |
| `ai-in-school` | ИИ в школе | Мектептегі ЖИ |
| `bilimai-news` | Новости Bilim AI | Bilim AI жаңалықтары |

## Тело поста

CommonMark и GFM-таблицы, без H1 (заголовок берётся из `title`), без HTML и JSX. Последний раздел — «Итог для учителя» / «Мұғалімге қорытынды». Бандл экранирует `{`, `}` и любой `<`, за которым не пробел (`\{ \} \<`); код (`` ` `` и ```` ``` ````) не трогается.

Ссылки — абсолютные `http(s)://` на `bilimai.kz` или `app.bilimai.kz` (и их поддомены) плюс якоря `#…`; `//host/…` и `www.host/…` считаются `https://` (как `_link_ok` в `apps/blog/lint.py`). Относительные ссылки и `mailto:` запрещены. Писатель ссылается токенами `{{feature:*}}`, бандл превращает их в `[Название](https://app.bilimai.kz/…)`. Ссылка на сам сайт `https://bilimai.kz/…` рендерится через `next/link`, остальные — обычным `<a>`.

## Валидатор

`src/lib/blog/validate.ts` разэкранирует тело (операция, обратная `bundle._MDX_SPECIAL_RE`) и повторяет правила `apps/blog/lint.py`. Ошибки роняют сборку, предупреждения печатаются строками `⚠ blog: …`.

| Ошибки | Предупреждения |
|---|---|
| пустое тело; H1; строка, начинающаяся с `<`, `{`, `import`, `export` | меньше 600 или больше 1800 слов |
| `{`/`}` вне кода, неразрешённый `{{feature:…}}` | цифры и «по данным» без источника; листикл «Топ-N»; эмодзи; знак `₸` |
| HTML-тег; `<` без пробела после | нет ни одного `## ` |
| ссылка на функцию продукта (бывший токен) внутри текста ссылки | kk: раздел похоже не переведён; в kk title/description почти нет казахских букв |
| ссылка вне allow-list, относительная (`/…`, `bilimai.kz/…` без схемы), `mailto:` | пара ru↔kk: разное число H2, длина kk/ru вне 0,8–1,25, тексты почти совпадают, разный набор ссылок на app.bilimai.kz, одинаковые title |
| фраза, выдающая языковую модель | пустой `coverAlt` |
| kk: казахских букв меньше 3 % кириллицы | имя обложки ≠ `cover-<sha1[:8]>.jpg`; размер JPEG не 1200×630 |
| title пустой или длиннее 70; description пустой, короче 50 или длиннее 160; `{}`/HTML в title или description | файл в `public/images/blog/<slug>/`, на который не ссылается ни один пост; экранированные `\{ \} \<` внутри кода (тело в админке с CRLF) |
| неизвестная рубрика или автор; `group` ≠ slug; `updated < date`; slug не из латиницы, цифр, `-` и `_` (как `SlugField`) | последний раздел — не «Итог для учителя» / «Мұғалімге қорытынды» |
| обложки нет, путь не `/images/blog/<slug>/….jpg`, файл больше 300 КБ | |
| ссылка `https://bilimai.kz/{ru,kk}/blog/<slug>` на несуществующий пост или черновик | `draft: true` — пост не попадёт в прод-сборку |
| ошибки грамматики фронтматтера и типов значений | |

**Известные расхождения с lint.** Lint проверяет сырое тело до подстановки токенов, лендинг — выгрузку, где токены уже стали ссылками `[Название](url)`. Поэтому у порогов могут быть мелкие расхождения:

- доля казахских букв около 3 % — названия функций в ссылках добавляют кириллицу;
- число слов — URL и названия считаются как слова.

Токенов в выгрузке нет, поэтому их роль играют ссылки на `app.bilimai.kz`: правила, которые lint проверяет по тексту без токенов (строка с `<`/`{`, фигурные скобки, HTML, `<` без пробела), здесь проверяются по тексту без этих ссылок, а «токен внутри текста ссылки» — это `[` без `]`, за которым идёт такая ссылка. Хост ссылки разбирается как `urllib.parse.urlsplit` (как `_link_ok`), а не по правилам браузера. U+2028/U+2029 не считаются переводами строк, как в Python.

## Маршруты и SEO

| Путь | Что |
|---|---|
| `/{ru,kk}/blog` | индекс: `CollectionPage` + `BreadcrumbList`. `openGraph.images` задан явно — `/<lang>/opengraph-image`, потому что `openGraph` без `images` убрал бы картинку сегмента |
| `/{ru,kk}/blog/<slug>` | пост, подробности ниже |
| `/{ru,kk}/feed.xml` | RSS 2.0; `lastBuildDate` = самый поздний `updated` (без постов — `SITE.contentUpdatedAt`) |
| sitemap | индексы блога и все посты, `lastModified` = `updated`, альтернативы по `group` |

Страница поста `/{ru,kk}/blog/<slug>`:

- `canonical`; hreflang — только существующие переводы, `x-default` → ru-версия;
- `og:type article`, `og:image` = абсолютный URL обложки, RSS-ссылка в `<head>`;
- JSON-LD: `Organization` (тот же `@id`, что на лендинге), `WebSite`, `WebPage`, `BlogPosting`, `BreadcrumbList`. Автор и издатель — `{"@id": ORG_ID}`; без `Person` и полей проверки;
- обложка — LCP-кандидат: `loading="eager"` + `fetchPriority="high"`.

Ссылка «Блог» есть в навигации и футере лендинга. RSS лендинга: `/ru/feed.xml` для ru и en, `/kk/feed.xml` для kk.

## Ловушки сборки

- **`generateStaticParams` поста** (`src/app/[lang]/blog/[slug]/page.tsx`) возвращает полные пары `{lang, slug}` всех постов и не смотрит на `params` родителя. Next вызывает его для каждого `lang` корневого layout (включая `en`). Если для какого-то `lang` вернуть `[]`, Next пропустит дальше `{lang}` без `slug`, сочтёт набор неполным и не пререндерит **ни одного** поста (`next/dist/build/static-paths/app.js`).
- **Контекст `import()`.** Тело поста грузится одним шаблоном `` import(`@/content/blog/${lang}/${slug}.mdx`) ``. Turbopack собирает контекст на сборке, и пустой контекст — ошибка сборки. Его держит непустым `_template/post.mdx` — не удаляйте этот файл.
- **Пути `node:fs`** в `posts.ts` — литералом от подпапки (`join(process.cwd(), "src/content/blog", lang)`). С переменной в начале пути Turbopack трассирует в серверный бандл весь проект.
- **Плагины MDX** в `next.config.ts` — строками (Turbopack не передаёт функции в Rust); свой `rehype-summary.mjs` — абсолютным путём, потому что `@next/mdx` резолвит строки от папки MDX-файла.
- **Окончания строк.** `.gitattributes` держит `.mdx` в LF: на Windows с `core.autocrlf=true` посты иначе станут CRLF.
- **Модули, которые импортирует `next.config.ts`** (`types.ts`, `frontmatter.ts`, `validate.ts`, `content/authors.ts`), — без path-алиасов `@/`.
